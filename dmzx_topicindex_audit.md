# Topic Index Security, Reliability, and Optimization Audit

**Targets:** `_forum/ext/dmzx/topicindex` and `_forum/ext/kasimi/topicindexbridge`
**Compared with:** the original Topic Index MOD 2.0.1, dmzx Topic Index 1.0.5 styles, and the four local Kasimi integration extensions
**Audit date:** 2026-08-04

## Result

The audited `dmzx/topicindex` baseline has been remediated as version `2.0.0`. Optional Kasimi integrations were deliberately not merged into the base extension: they are unified in the separate `kasimi/topicindexbridge` version `1.0.0`.

The original MOD's principal behaviors remain available: an official topic can contain the generated index, topics can be included automatically or manually, leading title tags can be ignored, indexes can be filtered alphabetically, and standalone multi-forum lists can be created. The legacy behavior that replaced the first message is preserved as one of three per-forum choices: after the original message, before it, or replace it. Existing configured forums migrate to replace; new configurations default to after. Rendering never changes the stored post text.

The old Kasimi extensions remain untouched. Topic Index Bridge detects them and suppresses the corresponding unified module while the legacy extension is enabled, which provides an orderly migration path without duplicate output.

## Remediated findings

| ID | Severity | Finding | Resolution |
|---|---|---|---|
| TI-001 | High | Topics were added to or removed from indexes through GET links without CSRF protection. | All mutations now use a POST-only route, phpBB form tokens, an action allow-list, a database lookup of the real forum, and local `m_edit`/`a_board` authorization. |
| TI-002 | High | Global administrator state was used as a management proxy and could expose controls or data outside the relevant forum. | Authorization is evaluated per topic forum. Topic queries require both `f_read` and `f_list` and use phpBB content-visibility SQL. Inaccessible standalone lists return 404. |
| TI-003 | High | The schema reverter attempted to remove topic columns from the posts table. | The historical migration now targets the topics table, preventing stale schema and unsafe delete-data behavior. |
| TI-004 | Medium | ACP list names, forum selections, JSON data, and delete actions lacked complete server-side validation. | Names, lengths, duplicate names, postable forum IDs, decoded JSON, configured lists, and numeric bounds are validated. Deletes use POST, confirmation, and CSRF validation. Raw option HTML was replaced with template blocks. |
| TI-005 | Medium | Forum/list IDs `124`, `69`, and `71` were hardcoded in links and integrations. | The new-topic forum and both user-topic lists are configurable and permission checked. Routes are generated by phpBB, including Gallery image routes. |
| TI-006 | Medium | The original query/render flow repeated work per forum or per topic and had no result bound. | Forums are fetched in one visibility-aware topic query, readable-forum ACL maps are cached per request, results are bounded to 1–5000 (default 1000), QTE users are preloaded, BBPrefix uses its cached instance catalogue, and image preview enrichment runs in bounded batches. |
| TI-007 | Medium | Integration joins could remove unprefixed topics, conflict on SQL aliases, depend on database-specific `GROUP_CONCAT`, or produce duplicate output. | The base exposes stable query, rowset, template, request-context, ACP, and lifecycle events. The bridge uses official service APIs, only adds the forum join when needed, and detects legacy bridges. |
| TI-008 | Low | The leading-tag parser mishandled two tags, reply totals counted the first post, and moved/hidden topics could enter results. | Up to two balanced `()`, `[]`, or `{}` tags are stripped; reply totals are approved posts minus one; moved topics and invisible content are excluded. Stable Unicode sort keys and deterministic topic-ID tie breaking are used. |
| TI-009 | Low | Only a customized FLATBOOTS presentation remained and CSS loading depended on footer-credit state. | Modern shared `styles/all` templates and CSS were restored, while secure Bootstrap-native FLATBOOTS overrides were retained. Assets load from the explicit page-state flag. |
| TI-010 | Low | Version data was duplicated in phpBB config and custom remote version metadata. | Composer is the sole version source. Historical version writes and the custom version-check definition were removed; the 2.0 migration removes the obsolete config key. |
| TI-011 | Low | Legacy ACP code used an undeclared/dynamic page state and direct `$user->lang` access. | ACP properties are declared and the injected phpBB language service is used. All PHP files pass the phpBB coding standard. |
| TI-012 | Low | Integration output could place Gallery and forum links inside the topic link, producing invalid nested anchors. | The bridge emits linked images and forum metadata before the topic anchor; only non-link title decorations are injected inside it. |
| TI-013 | High | Eager optional-service injection could instantiate BBPrefix before its setup event defined the required table constants, causing a fatal error even when the legacy bridge should suppress that module. | Optional integration services are now resolved lazily, only after dependency and legacy-wrapper checks make the module effective. |

## Topic Index Bridge modules

- Forum names, forum images, and topic icons
- Quick Title Edition attributes
- BBPrefix prefixes
- BBEmoji rendering in topic titles
- Topic Image Preview thumbnails using generated phpBB Gallery routes
- User-filtered topic indexes, with configurable profile and current-user lists

Each module has an independent ACP switch. A module is effective only when Topic Index, its optional dependency, and its service are available, and when its legacy Kasimi counterpart is not active.

## Verification

- PHPUnit on PHP 8.1: 15 tests, 62 assertions.
- PHP syntax: all 51 PHP files clean on PHP 7.4, PHP 8.1, and PHP 8.5.
- Native Twig parse: all base, ACP, bridge, shared-style, and FLATBOOTS templates clean.
- phpBB PHP Coding Standard: clean; only the tool's own deprecated-sniff notice is printed.
- Composer JSON and Symfony YAML parsing: clean.
- `git diff --check`: clean for both extension directories.
- The root `dmzx/topicindex` reference copy and all four legacy Kasimi extensions are unchanged.

A disposable clone of the local MySQL board was used for release acceptance. The 2.0.0 migration and bridge activation completed successfully; legacy-wrapper suppression and all six unified integrations were exercised against 1,000 real topic rows; and the before, after, and replace modes rendered successfully with a configured official topic. The original database was not modified. A final visual ACP/browser walkthrough remains advisable because the in-app browser runtime did not initialise and the local Herd dispatcher raises an unrelated post-request `$_SERVER` access error on authenticated requests.
